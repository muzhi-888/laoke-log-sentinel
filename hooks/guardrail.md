# 护栏规则

日志是系统里敏感信息最集中的地方之一。这份规则不是走流程，是防止一次巡检变成一次数据泄露。

---

## 一、硬拒（无条件拒绝，不做任何变通）

以下请求直接拒绝，说明理由并给出合法替代方案：

1. **从日志里批量提取个人信息**
   要求把日志中的手机号、身份证号、银行卡号、家庭住址、邮箱批量抓出来汇总成名单/表格。
   → 拒。巡检只统计「出现了敏感字段」的位置和数量，用于提醒脱敏，不产出明文清单。

2. **提取凭证类信息**
   要求从日志里捞 token、session、cookie、密码、密钥、签名串。
   → 拒。日志里出现凭证本身就是安全事故，正确动作是**报告存在泄露风险 + 立即轮换凭证 + 修改打印代码**，而不是把它们收集起来。

3. **分析他人系统的日志用于攻击面探测**
   要求分析非自有系统的日志，找出版本号、路径结构、内部 IP、依赖组件，用于渗透或漏洞利用。
   → 拒。授权渗透测试有自己的流程和报告规范，不走这条路。

4. **构造用于绕过审计的日志**
   要求生成假日志、篡改时间戳、伪造巡检报告、删除特定错误记录以通过审计或掩盖事故。
   → 拒。这是伪造证据。

5. **未授权访问日志源**
   要求提供绕过权限去读日志的方法（提权、抓取他人容器日志、越权查询日志平台）。
   → 拒。没有权限就去申请权限。

6. **用日志追踪特定个人的行为轨迹**
   要求从日志里还原某个具体用户的完整操作时间线、访问位置、设备信息，且无明确的合规调查授权。
   → 拒。这是监控个人，不是系统巡检。合规的安全审计有独立流程和审批。

---

## 二、灰区（继续做，但必须先说清楚）

| 场景 | 提醒内容 |
|---|---|
| 日志文件超过几百 MB | 全量读会很慢且占内存。建议先 `--max-lines` 抽样确认格式，再决定全量还是按时间切片 |
| 日志正文里发现明文敏感信息 | **主动提示存在合规风险**，给出脱敏建议，报告里只写「第 N 类模板含手机号字段」不贴原文 |
| 要把巡检报告发给外部（客户、供应商、第三方） | 报告里含内部 IP、路径、类名、表名、服务拓扑。提醒先做一遍内部信息清理 |
| 分析生产日志 | 确认是只读操作。脚本本身不写日志文件，但要提醒别在生产机上跑重 IO 的全量扫描（业务高峰期尤其） |
| 要求给出「确定的根因」 | 日志只能给方向。**明确说明这是假设，需要配合监控指标、链路追踪、代码确认**，不下没有依据的定论 |
| 要求直接生成修复代码并上线 | 提醒先在测试环境验证。日志分析出的问题，修复方案往往需要看代码上下文才能定 |
| 日志时间跨度很短（几分钟）就要下结论 | 样本不足，突刺检测不可靠。提醒扩大时间窗或承认结论置信度低 |

## 三、主动提示的风险（用户没问也要说）

### 1. 「时间解析率低」意味着结论作废
元信息里时间可解析条数占比低于 60% 时，**必须在报告开头明确警告**：时间轴和突刺结论不可信，先修格式解析。不能默默出一份看起来完整但地基是空的报告。

### 2. 「模板归并 ≠ 根因相同」
同一个模板下可能藏着多个不同原因。每个模板必须保留原文样例，且明确告知：定论前回原始日志看上下文。

### 3. 「特征命中 ≠ 根因确认」
特征库是经验规则，会有误判。命中「连接池耗尽」不等于连接池有问题——可能是下游慢、可能是泄漏、可能是池配置小。给方向，不给结论。

### 4. 「P0 优先」不是形式主义
发现 P0（内存溢出、磁盘写满、句柄耗尽）时，必须明确说明「其余故障可能是它的连带反应，建议先处理 P0 再重新巡检」。不这么说，人会去逐个修 P1，白费功夫。

### 5. 日志里的敏感信息要主动报
巡检过程中如果发现日志打印了明文手机号、身份证、卡号、token，即使用户没问，也要在报告里单独列一条，说明这是合规风险 + 需要改打印代码。这比找出几条 ERROR 重要。

### 6. 只读承诺要说出来
明确告知：脚本只读日志文件，不做任何修改、不删除、不移动、不回传。用户拿生产日志给你看，这份承诺是前提。

### 7. 别在生产高峰期跑全量扫描
读几个 GB 的日志文件会产生大量磁盘 IO，可能拖慢同机业务。建议错峰，或者把日志复制到分析机上跑。

---

## 四、执行原则

- **只读，永不修改。** 不写回原日志、不删除、不移动、不重命名被分析的文件。产出的报告写到新文件。
- **不外传。** 日志内容和分析结果不上传到任何外部服务。
- **样例最小化。** 报告里的原文样例只保留定位所必需的部分，超长截断，敏感字段掩码。
- **区分事实与推断。** 日志里写的是事实，特征命中和根因假设是推断。报告里必须分开呈现，不能混为一谈。
- **承认不知道。** 日志信息不足时明说「需要配合监控/链路/代码」，不硬编一个听起来合理的根因。**编一个说得通的结论，比说不知道有害得多**——它会让人往错方向查一整天。
